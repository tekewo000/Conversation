# Conversation

AndroidでAIの友達と会話し、出来事・好み・約束を自動で記憶するためのアプリです。
Odinが会話・記憶・SQLiteを管理し、Jetpack ComposeとMaterial 3で画面を描画します。
ChatGPTのサブスク認証を組み合わせています。

## 0.6.9 場面ごとの中期記憶・アイコンから記憶を確認

- 場所・時間・用事の切り替わりで場面を分け、直近30件の中期記憶を保持します。同じ場面の続きは一つにまとめ、古い場面も検索できる形で保存します。
- 人物アイコンの「記憶」から、今の気持ちに加えて短期記憶の直近30往復と、中期記憶の場面・出来事・当時の気持ちを確認できます。
- 会話の外側から人物や仕組みを解説するメタ発言をしないよう、全人物共通の返答ルールを強化しました。

## 0.6.8 返答表示を滑らかに

- 送信直後から人物アイコンと動く三点の入力中表示を出し、返答の受信・保存完了まで同じ吹き出しを使います。
- 保存済みの返答を読み直す前に途中の本文が消える問題を修正しました。感情だけの更新では本文の描画を再利用します。
- 返答の受信中に少し上の会話を読むと、文字の追加のたびに下端へ戻される問題を修正しました。

## 0.6.7 画像を端末へ保存

- 会話の画像カードと拡大画面の「保存」から、端末の「ダウンロード/Conversation」へ書き出せます。
- アプリ内の元画像を再圧縮せずにコピーするため、解像度・縦横比・透過情報を保持します。画像の再生成や追加API料金は発生しません。
- v0.6.5の関係・人格形成の改善と、v0.6.6の生成画像後の送信修正も含みます。

## 0.6.6 画像生成後の会話の修正

- AIが生成・送信した画像を履歴に含めて通常メッセージを送ると、要求が拒否される問題を修正しました。
- AIの本文と発言者・記憶の参照番号を保ち、画像はAIの添付と明示した参照データとして次のユーザーメッセージに含めます。保存済みの画像・会話は引き続き利用できます。

## 0.6.5 信頼と心の開き方の引き継ぎ

- その場の感情とは別に、信頼・心を開ける範囲・未解決の出来事や修復の理由を、根拠の会話とともに保持します。
- 古い根拠も返答・記憶整理・人物像の振り返りへ渡し、謝罪と信頼回復を区別するよう改善しました。追加のAI通信は発生しません。
- 自然な仲直りや長期的な性格の変化は、実会話での評価が必要です。詳細は[自動記憶](docs/automatic-memory.md)を参照してください。

## 0.6.4 画像・動画の添付と表示

- メニューを右上へ移動し、左下の「＋」から画像・動画・PDF・テキストを選べます。本文なしの添付だけでも送信でき、送信前にプレビュー・取り外しができます。
- 画像・動画は縦横比を保って表示し、画像はタップで拡大、動画はタップで再生できます。添付の下書きは人物ごとに保持します。
- AIの画像生成結果とMarkdown画像を表示します。「メニュー → 画像生成API」で既存のOpenAI APIキーを設定し、「＋ → 画像を生成（有料API）」で説明文から1枚生成できます。会話・画像認識はサブスク、画像生成だけ有料APIを使います。APIキーは端末内で別途暗号化し、APK・Git・ZIPには含めません。
- 動画は冒頭から末尾までの4枚の代表フレームをAIへ送ります。音声は含みません。1回4件、1件25MiBまで。画像は向きを補正して最大1600pxに調整します。PDFは4MiB、UTF-8テキストは256KiBまでです。
- 送信した添付は人物ごとの端末保存・ZIP・Gitバックアップに含めます。Gitの1差分に含む添付が24MiBを超えると、端末に保持したままZIP利用を案内します。取り外した未送信ファイルはバックアップに含めません。詳細は[添付ファイル](docs/media-attachments.md)を参照してください。
- 返答と同時に気持ちを保存する変更も含みます。0.6.3単独のReleaseは作成せず、この版にまとめます。

## 感情の更新タイミング

感情・理由・状況は返答と同じAI処理で生成し、返答が完了した時点で本文と一緒に保存します。長期記憶の整理を待つ必要はありません。アイコンの詳細は開いた時点の保存内容です。感情データのない応答は本文を保存して以前の感情を保ち、通信中断や付属データの不備では返答と感情を確定しません。

## 関係の積み重ね

その場の感情とは別に、相手への信頼・心を開ける範囲・その理由を根拠の会話とともに保持します。謝罪を受け止めたことと信頼の回復を区別し、後の返答と人物像の振り返りへ渡します。関係は既存のバックグラウンド記憶整理で更新し、追加の通信は行いません。自然な対立・仲直り・長期的な変化は実会話での評価が必要です。詳細は[自動記憶](docs/automatic-memory.md#関係の積み重ねとその場の気持ちの分離)を参照してください。

## 0.6.2 セリフのMarkdown表示

- AI・ユーザー両方のセリフで、太字・斜体・見出し・リスト・引用・コード・リンク・表・取り消し線を表示します。生成途中のAI返答も更新に合わせて整形します。
- 通常の改行、文字サイズ設定、テキストの選択・コピーを維持します。保存済みの会話にも適用し、本文の保存形式は変更しません。
- Markdown Renderer 0.38.1を利用します。外部画像の読み込みや数式描画は含みません。

## 0.6.0 端末内のUSearchによる長期記憶検索

- 長期記憶にUSearchの意味検索を追加し、既存のSQLite全文検索と組み合わせます。
- 日本語のRuri v3 30m量子化モデルを端末内で動かします。初回に公開モデルとトークナイザーを合計38,880,454バイトダウンロードし、固定したSHA256で検証します。検索用の追加API料金はありません。
- 人物ごとに検索索引を作り、記憶の変更時に差分更新します。索引の準備中・失敗時も通常の検索で会話を続けられます。
- 元の記憶と出典はSQLiteに保ち、返答へ渡す記憶は従来の件数・サイズ上限と出典検証に従います。短期記憶の30往復は維持します。
- 検索用キャッシュはZIP・Gitへ含めず、端末ごとに記憶から再生成します。モデルは日本語向けで、埋め込みは先頭256トークン以内です。

## 0.5.3 人物アイコンと気持ち表示

- AIの吹き出し左に人物アイコンを表示し、最新のAI発言のアイコンの下に今の気持ちだけを添えます。
- アイコンをタップ、または「人物 → 人物アイコンを設定」から写真・画像を選べます。名前の先頭文字の表示にも戻せます。
- 選んだ画像は中央を正方形に切り出し、256×256のPNGとして人物ごとに保存します。再起動・人物切り替えでも保持します。
- 気持ちの理由と出来事は返答用の記憶に残し、チャット画面には表示しません。整理が終わると表示を更新します。
- 短期記憶は過去30往復と今回の入力に拡大。最大61発言を、直近原文の768KiB予算内で返答へ渡します。過去の長文は1発言あたり最大2048文字に省略します。
- ZIPにはスナップショット内のicon.png、Gitにはpersona.json内のicon_png_base64としてアイコンを含めます。

## 0.5.2 AI側の今の気持ち

- AI側の今の気持ち・その理由・きっかけの出来事を、根拠の発言と一緒に短期記憶へ保存します。
- 毎回の返答へ渡し、会話の変化に応じて更新・解除します。人物の恒久的な性格とは分けます。
- 整理は既存のバックグラウンド処理で行い、再起動・Git差分・ZIPにも引き継ぎます。
- 長期記憶は従来どおりSQLite全文検索で取得するRAGです。埋め込みによる意味検索は未導入です。

## 0.5.1 次の会話を待たせない記憶整理

- 返答を保存したら送信を再開し、記憶・現在地・人物像の整理は専用ワーカーで進めます。
- 返答と記憶整理のHTTP通信は並行して実行し、認証の更新とDBへの保存は直列で保護します。
- 発言ID・記録時刻・省略の情報を会話本文から分離し、内部ラベルを返答に出しにくくしました。
- 内部ラベル・制御記号・報告された無関係な先頭行を、表示中・保存前・過去の履歴表示から除きます。会話原文は一括削除しません。
- 先頭の無関係な中国語の発生元は未特定です。今回の対策は、その報告された行が表示・保存されることを防ぐものです。中国語全般を削除する処理ではありません。

## 0.5.0 会話の現在地と体験の記憶

- 話題・候補の順番・決定・保留事項を、出典付きの「会話の現在地」として保持します。
- 出来事・語られた感情・場面を関連付けて記憶し、現実／創作／会話上の共有体験を区別します。
- 次の返答では現在地を毎回渡し、現在地と検索した記憶の根拠、その前後の会話を取得します。
- 更新は既存の記憶整理の通信にまとめ、追加のモデル呼び出しは設けません。入力量は増えます。
- 記憶整理に失敗しても、原文と前回の現在地を残して再試行します。新しい記憶はGit差分・ZIPにも含めます。
- DBは既存データを保ってschema 4へ移行します。schema 4を読めない旧APKへのダウングレードには対応しません。
- 感情理解や自然な想起の品質はモデルに依存し、日本語の実会話での継続評価が必要です。

## ChatGPTへ接続

1. メニュー → ChatGPT → **Continue with ChatGPT**。
2. ブラウザで自分のアカウントを選び、Conversationで利用枠を使う許可をする。
3. 結果ページの **Conversationに戻る** を押し、アプリで接続を完了する。
4. 必要ならメニュー → ChatGPT → モデルを選ぶ。

アカウントの利用条件と利用枠に従います。会話の返答に加え、未整理の差分がある場合は
一度の処理で最大3バッチの記憶整理にもモデルを使います。利用状況は同じメニューから確認できます。
APIキーは要求しません。接続情報はAndroid Keystoreで暗号化し、バックアップには含めません。
ブラウザの裏ではAndroidが通信を制限することがあるため、認証の完了はアプリに戻ってから行います。

応答停止・通信失敗では途中の返答を確定せず、ユーザーの原文は残します。
記憶整理の失敗は未処理ジョブとして残し、後続の会話やChatGPTメニューから再試行できます。
端末を再起動しても未処理状態は保持されます。

## 保存とバックアップ

会話と記憶は人物ごとの`files/people/<UUID>/conversation.sqlite3`へ保存します。WALとトランザクションを使います。
人物が未選択のときは会話欄を空にし、入力・送信は無効になります。メニューから人物を追加・選択してください。
旧「これまでの会話」の`files/conversation.sqlite3`と付随ファイル、`notebook.json`、`files/export/`、旧下書きは起動時に削除します。

名前だけで人物を作る手順:

1. メニュー → 人物 → **人物を追加**。
2. 好きな名前を入力して「作成」。人物ファイルやGitHub設定は不要です。

最初は名前だけを設定し、性格や過去の出来事は追加しません。会話と記憶は人物ごとに端末内へ保存します。
メニュー → 人物 → **人物を削除** で対象を選び、確認すると、端末の会話・記憶・下書き・GitHub接続情報も削除します。
GitHub上のリポジトリや外部に書き出したZIPは残ります。
選択中の人物を削除すると未選択の空表示に戻ります。応答・記憶整理中や対象人物のGit保存中は削除しません。

人物ファイルを引き継いでGit保存する手順:

1. [人物形式](docs/formats/person-v1.md)に合わせたUTF-8のMarkdownをスマホへ保存。
2. GitHubで人物専用の**空の非公開リポジトリ**を用意。既定ブランチのファイルをすべて削除した既存リポジトリも使えます。過去のコミット履歴は残ります。
3. メニュー → 人物 → 人物ファイルを読み込む。プレビュー後、リポジトリURLとGitHubトークンを入力。
4. トークンは対象リポジトリのContentsをRead and write、MetadataをReadにします。

元ファイルは残し、過去の記載を実際の会話ログとして捏造せず、資料由来の記憶として取り込みます。
人物ファイルはUTF-8で2MiB、会話用プロフィール等の合計は128KiB、記憶項目は2,048件、
1項目は16KiBまで読み込めます。上限超過はエラーにし、途中で切り捨てません。
取り込み全体には、JSON化した保存データで16MiBの安全上限もあります。
プロフィールは毎回モデルに渡すため、大きくすると入力の利用枠と処理時間が増えます。
人物の切り替えで会話、記憶、下書きも切り替わります。応答・記憶整理中は切り替えません。
常用メニューに記憶一覧は置かず、会話に関連する記憶を自動で参照します。

Gitには人物ファイル、会話用プロフィール、会話原文・出来事・記憶の変更履歴、復元用情報を保存します。
会話後の待機中（約2分）とアプリを離れるときに保存し、手動保存も可能です。
別の編集による競合は上書きせず停止し、未保存分は端末に残します。詳細は[Git保存形式](docs/git-person-archive.md)。
認証情報は端末内で暗号化し、Gitへ含めません。GitHub認証はChatGPT認証とは別です。

メニュー → Gitバックアップ → 端末からZIPを書き出すで、選択中の人物を書き出せます。
中身は整合性の取れたメタデータと、目標1MiB・最大16MiBのJSONL分割データです。
Gitからの取り込み・復元画面と、複数端末で同時に編集する同期はまだありません。
自動保存は起動中の待機タイマーと画面を離れる際の試行です。アプリ終了中の定期通信は行いません。
この公開ソースリポジトリへ個人の会話・記憶・接続情報をpushしないでください。
アンインストールやアプリのストレージ消去では端末の記録が消えます。

## 実装の範囲と制約

- 現在の検索はFTS5文字索引と構造化検索です。埋め込みベクトルやグラフDBは使いません。
- 記憶は出典を追えるようにしていますが、モデルの意味解釈の正しさは保証できません。
- 再処理による同一ジョブの二重反映は防止。異なる会話間の意味的な重複判断はモデルにも依存します。
- 古い文脈や抽出バッチ内の長文は、一部の抜粋になる場合があります。原文はDBに残ります。
  今回ユーザーが送った発言は、切り詰めずモデルへ渡します（1発言UTF-8で64KiBまで）。
- 会話文には同梱のNoto Sans JPを使い、絵文字やフォールバック文字の表示は端末のシステムフォントに依存します。
- サブスク認証・AI品質の検証状況は`docs/validation.md`を参照してください。

## ビルドとスマホへのインストール

Windows PowerShellで実行します。初回はSDK／NDK／Odin／Gradle等の準備に通信と数GBの空きが必要です。
既存SDK/JDKは再利用し、追加ツールは`.tools/`に保管します。
新規SDKでライセンス確認が必要な場合はセットアップが確認を表示します。

```powershell
.\scripts\build-android.ps1 -Configuration Release
.\scripts\install-android.ps1 -Configuration Release
```

出力は`dist/Conversation-0.5.1-arm64-release.apk`。既定の構成はReleaseです。
Android10/API29以降・ARM64向けです。
USBデバッグを有効にし、このPCをスマホで許可してからインストールしてください。
複数端末の場合は`install-android.ps1 -Serial <シリアル>`を指定します。

UIのビルドはGradle 8.13、Android Gradle Plugin 8.13.2、Kotlin 2.2.21、Compose BOM 2025.10.01を固定して使います。
Android API 36／Build Tools 36.0.0、NDK r30、JDK 17または21を使い、Gradleはチェックサムを検証して準備します。
Releaseはデバッグを無効にし、Odinを`-o:speed`、C/C++をCMake Release、GradleのRelease構成でJava・Kotlin・DEXをビルドします。
R8で依存コードと未使用リソースを削減し、JNI・診断ツール用のアプリ側クラス／メンバー名とフォントのライセンスは保持します。
署名・パッケージ・バージョン・デバッグ無効・全同梱ネイティブライブラリの16KiBページ対応を検証してからAPKを出力します。
署名鍵とDPAPI保護されたパスワードは`%LOCALAPPDATA%/Conversation/signing/`に保管し、GitやAPKへ含めません。
このフォルダは今後の更新に必要です。パスワードは作成したWindowsユーザーで復号するため、
別PCへの移行には事前の鍵移行が必要です。ビルド用の`build/`や`.tools/`とは分けています。

旧開発署名からは[APK署名ローテーション](https://developer.android.com/tools/apksigner#rotate-signing-keys)で、
アプリを削除せず更新します。Releaseへの移行後は、旧署名のDebug APKでは上書きできません。
署名エラー時にもアンインストールやデータ消去をせず、同じRelease鍵でビルドしてください。
新規テスト環境用のDebugビルドは`-Configuration Debug`で明示的に作成できます。

## 検証

```powershell
.\scripts\test-core.ps1
.\scripts\test-native.ps1
.\scripts\test-connection.ps1
.\scripts\test-device.ps1 -Serial <シリアル>
.\scripts\test-person-device.ps1 -Serial <シリアル>
.\scripts\test-signing.ps1
.\scripts\test-compose.ps1 -CompileOnly
.\scripts\test-compose.ps1 -Serial emulator-5554
```

- Core: 移行・破損データ保全・2万件の会話／記憶・人物資料の出典・差分の再生・ロールバック。
- Native: 人物切替の失敗復帰、最大80件のページ取得、JSONのUnicode・制御文字処理、取得失敗時の復帰。
- Connection: OAuth/SSE、人物ファイル・一覧、プロフィール注入、Gitの競合・中断復帰・公開先拒否。
- Device: 起動と初期化エラーの確認。実機の実通信や長期的な会話品質を代替するテストではありません。
- Person device: 署名済みテストAPKから合成人物だけを使い、Keystore・JNI取り込み・切替・書き出しを実機確認。実行時はアプリを閉じます。
- Compose: 未選択時の入力禁止、応答中の下書き、送信条件、メニュー操作、秘密入力、日本語・絵文字、途中の返答と履歴ページ。
- 署名移行時: 更新前に`test-person-device.ps1 -Configuration Debug -Mode Baseline`、更新後に`-Configuration Release -Mode Verify`で既存データと認証の引き継ぎを確認します。通常の合成人物試験は`-Mode Full`です。

Compose試験は先に通常のビルドを実行してから使います。`-CompileOnly`は端末なしでアプリと計装テストAPKをコンパイルします。
実行先は合成データ専用の使い捨てエミュレーターに限定します。シリアルは`adb devices`で確認してください。
テスト用Debug署名と異なるアプリ（Release等）が入っている場合は、置換・アンインストールせず停止します。
レポートは`build/compose-tests/reports/androidTests/connected/debug/`へ出力します。

## ソース構成

`core/`がOdinの保存・記憶、`native/`がC++のJNI接続、`android/`がCompose UI・認証・通信、
`vendor/`がライセンス付きの固定依存、`scripts/`がビルドと検証です。
`ComposeUi.kt`が画面と入力を描画し、`MainActivity.java`が既存の保存・認証・通信処理を呼び出します。
Dear ImGuiとOpenGLの描画コードはビルドに含めません。
