## 独立レビューと回帰

1回の独立した全変更レビューで、4件の重要指摘とPC移行状態の書込みに関する指摘が出た。後者も、約束した再開性への影響から重要として同じ修正工程で対応した。

- `.tmp`が本来の保存先のAADで暗号化されている場合の再開を修正。正しい中断ファイル、画像pending、未完成断片の暗号化保持を確認。
- キー取得エラーをDBの保護エラーで包み、整理途中DBや意味検索キャッシュが削除されないことを確認。
- 下書き保存失敗時は人物切替等を止め、人物・入力・添付選択を保持することを確認。
- 未登録人物、未確定一覧、旧DBの孤立WALを検出して原本を残し、平文のまま通常利用へ進まないことを確認。
- PCのjob状態をsync＋atomic moveで採用し、書込み失敗で旧状態を失わず、完全なpending状態から再開できることを確認。

修正前に各不具合を再現し、修正後の対象11試験と全体83試験を成功させた。実旧Releaseの更新で見つかったWITHOUT ROWIDのFTS設定テーブルも回帰に加え、論理列順の照合へ修正した。重要指摘の修正後に別のレビューを重ねる方式は採らず、回帰と全体試験で検証した。未対応の軽微指摘はない。

## 実装中の判断

- mainを保護するため隔離worktreeを使用。既存の無視対象ツールキャッシュを共有し、WindowsのNinjaパス長制限に対して作業先へW:を割り当てた。成果物の依存・アラインメント・署名を実物で照合し、共有キャッシュや短縮パスによる取り違えを検査した。
- 一時的な製品キーを作らず、Task 1から共通のHKDF実装へ接続した。キー規約の誤りは全復元を妨げるため、RFC5869ベクタ・用途/人物/パスの分離・別キー拒否を検証した。
- 保存方式と既存データの移行は相互依存するため、中間状態のUI失敗を完了扱いにせず、Task 1〜3を統合して検証した。
- 暗号化後も動画/PDF等を使えるよう、seek可能な読み取り専用メモリ経路を追加した。平文キャッシュを作らず、動画再生とランダムアクセスを検証した。
- 公開が計画の最終タスクに含まれていても、独立レビューと修正・署名済み試験を公開より先に実施した。
- レビュアーが判断を保留した実Release、実ホスティング認証、実機、敵対的なGit設定の全組合せについて、推測で成功とせず、下記の範囲を分けて記録した。

## 未検証・境界

物理端末、実ユーザーのGit履歴、実GitHub/LFS認証・アップロードを使った移行、実OpenAI通信、初回モデルダウンロード、物理ストレージの停電耐久性は未検証。ローカルGitとエミュレータの成功をそれらの証明として扱わない。Gitの全設定・hook/filterの敵対的組合せを網羅したとは主張しない。

元Gitや既存のclone/ZIPは自動で変更・削除しない。移行用の一時mirrorと照合出力には平文を含み、成功後の削除はフラッシュの安全消去を保証しない。明示的な画像保存と復元出力も通常ファイルになる。
