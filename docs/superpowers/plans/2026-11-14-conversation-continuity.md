# B方式：会話の現在地と体験の記憶

ユーザーは2026-11-14にB方式の実装とリリースを指定した。設計専用の段階を終え、この計画で実装・検証・公開まで行う。

## 採用する構成

既存の記憶抽出要求で、従来の `memories` と一緒に `continuity` を生成する。追加の通信要求は設けない。`continuity` は最大6件の話題（候補・順序・決定・保留を含む）と最大6件の体験（出来事・感情・場面・現実と創作の区別）を、根拠の発言ID付きで保持する。長期の出来事は既存の `event` 記憶にも残す。

SQLiteに追記専用の `continuity_revisions` を加え、記憶抽出ジョブの確定と同じトランザクションで現在地を確定する。既存schema 1〜3を4へ移行する。根拠は今回のジョブ、直前の保存済み現在地、今回の抽出へ渡す直近の発言に限定する。古い形式の抽出結果は互換受け入れし、現在地を消さない。

次の返答では、現在地を毎回渡し、そこにある根拠と検索した記憶の根拠、その前後の会話を別予算で取得する。現在地の発言IDへ直接戻れるため、最新入力に検索語がない場合も元の相談を参照できる。長い原文は範囲を制限して取得し、一部しかないことを明示する。全履歴を毎回ロードしない。

現在地の更新失敗はジョブを未処理のまま残し、原文と前回の確定状態を保つ。更新位置を返答へ渡して、未処理の情報を古い現在地より優先する。感情は本人の明示・伝聞・推測を分け、推測は既存の `interpretation` へ保存する。新しい体験の確定記録では、感情や場面の不明部分は空欄にし、創作・現実・共有体験を区別する。

## 作業と対象ファイル

1. `core/continuity_test.odin` を追加し、古い候補・感情・場面の原文取得、不正根拠の拒否、失敗時の原子性、再起動、旧DBの移行、差分復元・ZIP対象の保持を検証する。機能のない現行コードで失敗することを確認する。
2. `core/continuity.odin` を追加し、保存スキーマ、現在値の取得、入力検証、追記を実装する。`core/conversation.odin` で移行、抽出ジョブの原子的確定、現在地と原文の取得、スナップショットへ接続する。`core/archive.odin` で差分・復元の検証へ接続する。
3. `android/tests/jp/tekewo/conversation/ChatSessionTest.java` で現在地が応答と抽出に届くこと、過去の補助原文がジョブの境界を越えないこと、切り詰めの通知を検証する。`android/src/jp/tekewo/conversation/ChatSession.java` で指示と参照データを変更する。既存のStore・JNI・C ABIの公開関数は再利用する。
4. `core/conversation_test.odin` と `core/persona_test.odin` の文脈上限・schema期待値を新契約へ更新する。新しい上限は直近原文18,000バイト、追加根拠20,000バイト、記憶10,000バイト、現在地12KiB。人物プロフィールは従来の別枠を維持する。
5. `android/AndroidManifest.xml` を0.5.0/code 10へ更新し、`README.md`、`docs/automatic-memory.md`、`docs/git-person-archive.md`、`docs/validation.md`、`design_draft.md` を実装と検証結果に合わせる。
6. Core、Native、Connection、署名、Composeコンパイル、Releaseビルドを実行する。接続端末が利用可能ならデータを消さずに更新し、起動を確認する。
7. ソースをコミット・pushし、v0.5.0のGitHub Releaseへ署名済みAPKを添付する。公開結果・添付ファイルのチェックサムを照合する。

## 検証の限界

合成テストでは、モデルへ適切な状態と根拠が渡ること、誤ったデータが確定されないことを確認する。実際のモデルが感情を適切に理解するか、長い日本語の雑談が自然につながるかは、ユーザーがログインした実会話で別に確認する。ユーザーの私的な履歴や認証情報をテスト・公開に使わない。
