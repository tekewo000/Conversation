## 判定

**現稿は、刷新する理由と範囲を確認する草案として読める。ただし、完成した機能仕様としての承認や実装開始には進めない。**

文書から、チャットを維持して、それ以外の管理画面を記憶も含めて刷新する意図は読み取れた。不要な新機能や新しい状態管理基盤を追加する提案はなく、既存の保存方式や秘密入力の保護も維持対象としている。

一方、記憶の用語、会話補助パネルの範囲、現状の説明には明確化が必要である。画面構成・状態管理・代替案・検証方法は今後作成すると明記されている。後者は初期草案として隠された欠陥ではないが、完成仕様や実装計画として評価すると未充足になる。

## 実装を読んで補足できたこと

これはレビューの参考情報であり、設計書本文を修正したものではない。

* 現在の中期記憶画面は `continuity.episodes` の体験一覧を表示し、体験から子の詳細へ進む構造になっている。C6-01の解消には、この画面上の対応を説明すればよく、新しい記憶の種類や閲覧機能を作る必要はない（[MainActivity.java](../../../android/src/jp/tekewo/conversation/MainActivity.java) の730–733、769–845行）。
* 人物削除と再整理は確認画面を持つ。ログアウトとAPIキー削除は行の選択から実行する。現在の確認を維持する要件と、確認の新設を決めることは区別する（同741–766、882–890、527–534、566–569行）。
* 既存の非同期処理には、人物ID、画面種別、要求番号の照合がある。画面刷新のために別の管理基盤を追加すると決めず、まずこれらをどう引き継ぐか比較する（同694–735、814–844行）。
