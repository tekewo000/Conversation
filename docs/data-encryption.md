# 個人データの保存暗号化

v0.10.0以降、人物ごとの既存画像キーで会話・記憶・人物資料・下書き・全添付・検索キャッシュ・整理作業DB・Git/ZIPバックアップを保護します。認証情報は従来の別のAndroid Keystore保護ストアを維持し、人物バックアップに含めません。

初回の利用前に旧データを移行します。旧DBのWALにある確定済み更新も反映し、SQLCipherへのコピー後に全テーブルの内容と整合性を照合して採用します。移行失敗時は平文で通常利用を続けず、元データを保持して停止します。未分類の旧root履歴が残る場合も、勝手に削除しません。

DBはSQLCipher Community 4.20.0で主DB・WAL・ジャーナル・FTS索引と両作業キャッシュを保護します。人物情報、下書き、動画/PDF/テキストはCDAT v1形式です。既存CIMG v1写真の読込規約と復元キー形式は変わりません。

CDAT v1は`CDAT`＋バージョン1バイト、nonce 12バイト、AES-256-GCM暗号文、認証タグ16バイトです。人物の画像キーからHKDF-SHA256で用途別鍵を導出し、人物ID・用途・論理パスを認証に含めます。旧画像と新しい一般ファイルでnonceや認証対象を混用しません。

アプリの通常利用ではキーを自動で使います。キーが読めない場合、新しい鍵に置き換えたりDBを消したりせず、「復元キーを読み込む」から保管済みの写真用キーを戻せます。バックアップは「データの復元キー」の書き出しが完了するまで停止します。

動画とPDF等の閲覧には、メモリ上で復号した内容を読み取り専用のseek可能なContentProvider/MediaDataSourceから渡します。平文の再生キャッシュは作りません。ユーザーが明示的に画像を保存した場合は、通常画像としてダウンロードへ書き出します。

人物一覧の起動用ファイルは不透明な人物ID・選択IDと、人物のキーで暗号化したメタデータを持ちます。サイズ、更新時刻、人物数、不透明なID、汎用ファイル名まで秘匿するものではありません。モデル・フォント・ライセンス等の公開資産や、文字サイズ等の非個人設定は暗号化しません。

Git/ZIPの外側は固定形式の`format.json`、暗号化した`archive.enc`、不透明名の`objects/*.enc`です。認証付きマニフェストで元のパス・内容指紋・暗号文指紋・サイズを検証します。Gitのexpected-HEADと既存の再送検知を維持し、同じ論理内容を乱数nonceの違いだけで別バッチと扱いません。

過去のGitを含む移行・PCでの復元方法は[Git移行手順](git-backup-migration.md)を参照してください。旧Gitリポジトリを引き続き平文で更新することはありません。

この暗号化は保存時の保護です。利用中アプリのメモリを読める攻撃、AIサービスへ明示的に送った内容、書き出した通常画像、他の保存先の既存コピーを暗号化・削除するものではありません。
