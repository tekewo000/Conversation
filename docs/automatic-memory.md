# 会話するだけで続く自動記憶

2026-11-13 のユーザー指定：普段は会話するだけでよく、手動で記憶に登録する操作は必要ない。

## 実装する流れ

1. 会話の原文を端末に保存する。
2. AIの返答が確定した後、未整理の会話から出来事・好み・約束・関係の変化を抽出する。
3. 発言元と時点を紐づけ、既存の記憶との重複・変更・矛盾を確認して保存する。
4. 次の会話では、現在の話題に関係する記憶を自動で取り出す。

通常の抽出・保存に確認ボタンや承認画面は挟まない。利用者が気になった時だけ
記憶を確認・訂正できる。手動固定の操作は設けない。嘘・推測・創作中の設定を、現実の確定事実と混ぜない。
好みが変化した場合は過去の出来事を消さず、現在の情報と変更時点を記録する。

抽出の失敗や通信切断で会話原文を失わない。未整理の会話は後から再処理でき、
同じ会話を再処理しても二重登録しない。再生成で捨てた返答は記憶の根拠にしない。
記憶抽出もサブスク利用枠を消費するため、未変更部分を毎回読み直す処理は避ける。

## 現在の実装状態（0.2.0）

SQLiteへの追加保存、旧JSONの一度限りの移行、80件ページ表示、出典付きの型付き記憶、
更新履歴、取り消し可能な約束の状態、差分整理ジョブ、索引検索、関連原文の取得を実装した。
事実・出来事・約束は明示された情報に限定し、推測は解釈として区別する。
異なる人物・キー・種類・世界の記憶を置き換える処理は拒否する。

モデルへの現在の発言は全文を渡し、古い文脈と整理バッチはサイズ制限付きで処理する。
長文の一部しか渡せていない場合はtruncatedを明示する。全文はDBへ保全する。
検索はFTS5の日本語文字索引と構造化検索で、埋め込み検索やグラフDBは未導入。

ChatGPTの認証と実際の応答・記憶整理を接続した。アプリへ戻ってからトークン交換を
完了する。応答はSSEまたは完了状態のJSONを検証して確定し、途中の返答は原文にしない。

手動固定・全文一覧・全文コピーは設けない。過去の旧固定記録は互換データとして保全し、
通常の自動抽出とは区別して表示する。AIの意味解釈・矛盾判定の完全性は保証しない。
長期間の日本語会話、暗黙の想起、人物像の維持、過剰な記憶利用は今後の実会話評価が必要。

## 人物自身の緩やかな変化

出来事の記憶とは別に、会話する人物自身の好み・相手との関係・考え方・話し方・気質を
出典付きの現在の人物像として保持する。ユーザーのプロフィールを人物にコピーする処理にはしない。
現在の人物像は検索した記憶の最大12件とは別枠で毎回の返答と記憶抽出へ渡し、
引き継ぎプロフィールと衝突するときは対応する項目だけを優先する。名前や経歴、未更新の設定は保つ。

返答を保存し、通常の記憶を最大3バッチ整理した後、人物像の振り返りを最大1回行う。
通常の記憶ジョブがないときも振り返りは再試行できる。原文は古い発言を含めて範囲とサイズを制限し、
切り詰めた発言にはtruncatedを付ける。モデルへ渡した原文のIDだけを更新の根拠に認める。

12件以上の新しい発言で振り返りを予定し、1回で進める範囲は最大24件とする。
好みと関係はuser・assistantそれぞれ2件以上の根拠が必要で、考え方・話し方・気質は
それぞれ6件以上、発言IDで24以上の幅と前回変更から24以上の間隔を必要とする。
どの変更にも前回の振り返り後のuser・assistantの根拠を最低1件ずつ含める。
一時的な気分、ロールプレイ、その場だけの命令や自己紹介の反復を恒久的な変化にはしない。

変更なしも正常な結果として振り返り済みの位置を進める。更新・通信が失敗した場合や中断時は
人物像を確定せず、保存済みの会話と返答を残したまま後から再試行する。
モデルの解釈や実際の話し方への反映は、自動テストに加えて実会話での評価が必要。

DBはschema 3へトランザクション内で移行し、schema 1/2の会話・出典・人物資料を保つ。
人物像の変更と変更なしのチェックポイントも、Gitの差分履歴とZIPのスナップショットへ含める。
schema 3に対応しない旧CoreはDBを開かず、人物像を無視した書き出しを防ぐ。
回数・間隔は会話数による初期の目安で、独立した経験や自然な成長を機械的に証明するものではない。
現在像の生成は変更履歴を読むため、大量履歴での実機負荷は別途測り、必要なら現在値を実体化する。

## 0.5.0：会話の現在地と体験

既存の抽出結果 `memories` に `continuity` を加え、同じ通信で更新する。最大6件の話題には候補・順番・決定・保留を、最大6件の体験には出来事・明示された感情・場面・現実と創作の区別を保持する。各項目に根拠の発言IDを1〜8件付け、現在地全体はJSON化後12KiBに制限する。感情と場面の不明部分は空文字とし、推測の感情は既存のinterpretation/inferredへ分ける。保持枠から外れる長期の出来事は、既存のevent記憶にも残す。

現在地の改訂は `continuity_revisions` に追記する。記憶・現在地・ジョブの処理済み位置を同じトランザクションで確定し、検証失敗時はまとめて取り消す。根拠IDはジョブの発言と直前12発言、または前回の現在地が保持する出典に限定する。抽出に渡す補助原文はジョブの終端以降を除外する。従来形式の抽出結果も受け入れ、その場合は現在地を消さない。

返答へは最新の現在地とthrough_idを毎回渡す。現在地の根拠と検索した記憶の根拠、その前後1発言を、直近12発言とは別の予算で取得する。原文は最大2048文字の抜粋であり、長文の省略を明示する。直近原文18,000バイト・追加根拠20,000バイト・検索記憶10,000バイト・現在地12KiBを上限にする。人物プロフィールと人物像は別枠、今回のユーザー入力は従来どおり全文を渡す。原文全体はDBに残る。

現在地より新しい発言の訂正・決定を優先し、過去の感情を現在の気持ちや恒久的な人物像と同一視しない。保存時の検証は形式・出典範囲・上限を確認するもので、モデルの感情解釈が正しいことを証明するものではない。
