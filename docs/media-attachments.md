# 添付ファイル

右上にメニュー、左下に追加ボタンを配置する。追加から画像・動画、PDF・UTF-8テキストを選ぶ。プレビューから取り外せる。通常の会話・画像認識・動画の代表フレーム解析・記憶整理は既存のChatGPTサブスク接続を使用し、画像生成だけ有料のOpenAI Image APIを使う。画像生成は次の送信に対して明示的に選ぶ。

## 保存と送信

選択したデータは人物の `media/<SHA256>.<extension>` に保存してから使う。本文には `![名前](attachment:<SHA256>.jpg)` または `[名前](attachment:<SHA256>.mp4)` のような参照を保存する。画像やBase64をSQLiteの会話本文へ埋め込まない。既存のメッセージ・感情・ジャーナルの保存処理を利用する。人物切り替え、再起動、再試行でも同じ参照を使い、添付の下書きは人物別に保存する。

1回4件まで。1ファイル25MiBを超えると読み込みを拒否する。画像はImageDecoderでEXIFの向きを反映し、縦横比を保って最大1600pxに調整する。透過画像はPNGのアルファを保ち、不透明な画像はJPEGを使う。PDFは4MiB、テキストはUTF-8の256KiBまで。動画は元ファイルを保持する。画像・動画のプレビューは横幅と高さの枠内へ縦横比を保って収め、画像の拡大はContentScale.Fit、動画はVideoViewのプレイヤーを使う。PDF・テキストは読み取り権限だけを付けたFileProvider URIで外部ビューアーへ渡す。

Responses APIには画像を `input_image`、PDFを `input_file`、テキストを `input_text` として渡す。動画は0秒から末尾直前まで均等に4フレームを抽出し、時刻を添える。キーフレームだけで代用せず、指定時刻に近いフレームを復号する。動画音声は送らない。1要求で画像24枚・PDF4件を上限として新しい発言を優先する。添付の送信容量は12MiB以内に収め、過去の添付は容量超過分を再送せず、その旨をモデルへ伝える。今回の添付が超過した場合は一部を黙って落とさず、減らして送信するよう案内する。要求全体が16MiBを超えると送信を拒否する。

画像生成時は `POST https://api.openai.com/v1/images/generations` に入力中の説明文だけを送る。過去の会話・記憶・プロフィール・添付は送らない。生成モードで添付がある場合は送信前に取り外しを案内する。既定モデルは `gpt-image-2.5-flare`（アプリで変更可能）、1枚、品質medium、サイズauto、PNG。`data[0].b64_json` を画像として検証・保存し、通常のAI発言に添付参照を記録する。感情データをこちらで捏造・解除しない。生成画像は10MiB、API応答は16MiBを上限とする。通常会話のSSEには画像生成ツールを要求せず、テキスト上限は従来の2MiBを保つ。

## 画像生成用APIキー

「メニュー → 画像生成API」で既存キーを入力する。入力画面はパスワード表示とFLAG_SECUREを用い、キーは表示し直さず、空欄の保存では既存キーを保つ。ConnectionStoreの既存AES-GCM/Android Keystore保存を使い、別のalias/AADと `noBackupFilesDir/image-api-connection.v1` へ保存する。従来のChatGPT接続のalias・AAD・ファイル名は維持する。APIキーの削除や再設定はChatGPTの接続に触れず、キーをAPK・Git・ZIP・通常の設定へ埋め込まない。

画像生成を選んだ場合だけ有料APIを呼び、自動再試行はしない。再生成ボタンにも有料と表示する。停止・Activity破棄でHTTP接続を切り、応答が届いてもキャンセル後には会話を確定しない。通信切断はAPI側の課金取り消しを保証しない。API側のモデル権限・残高・必要な組織認証は利用者の設定に依存する。

現行のChatGPT token-sharing接続は画像生成ツールに非対応であるため、この有料経路と分離する。[公式の制限](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)、[Image APIの仕様](https://developers.openai.com/api/docs/guides/image-generation)。

HTTPSのMarkdown画像も取得・保存して表示する。外部画像への要求にChatGPTの認証情報は付けず、HTTP・ユーザー情報付きURL・ローカル/プライベート宛先とそのリダイレクトを拒否する。取得できない画像は開けるリンクを表示する。既存履歴のMarkdown画像は表示時に処理し、保存済みの本文を書き換えない。

## バックアップ

ZIPには現在のスナップショットの会話が参照するファイルだけを `media/` として追加する。未送信・取り外し済みの添付は含めない。Gitは今回のジャーナル差分が参照するファイルだけを追加し、ファイル名と内容のSHA256を照合する。参照だけ保存してバイナリを黙って欠落させない。

Gitは1回の差分でバイナリ24MiBまで。超えた差分はカーソルを進めず、端末に全データを保持したままZIPバックアップを案内する。端末内で取り外した未送信ファイルの自動掃除は行わない。同じ内容を過去の送信や下書きが再利用している可能性があるため、人物削除時にまとめて削除する。

## 検証

- Java: ファイル永続化・重複排除・サイズ上限・途中ファイル掃除・パス検証・改ざん拒否・ZIPとGitへのバイナリ同梱・未送信ファイルの除外。
- 有料API: 要求が説明文だけを含むこと、1枚・medium・auto・PNG、2MiB超の応答画像、APIキー形式とヘッダー注入拒否、安全なエラー表示。通常の会話では画像生成ツールを付けないこと。
- Android: 実画像と4色のMP4から作る5枚の画像入力、4色の時間順と縦横比、生成画像の端末保存、画像だけの下書きと取り外し、両発言者の画像と比率、画像拡大、動画の実再生と終了、右上メニュー・左下追加ボタン。
- Android: APIキー保存が暗号化され、ChatGPT接続情報を変更せず、キー入力が保護された画面で伏せ字になること。
- Release: 従来のONNX JNI名検証と起動・推論試験を行う。`test-release-startup.ps1 -Serial <device> -Media` は接続済み実機で合成画像の文字認識を試す。会話・記憶の行は作成せず、サブスク利用枠は消費する。有料キーは利用者がアプリ内で入力するため、エージェントによる実際の有料画像生成は行わない。
